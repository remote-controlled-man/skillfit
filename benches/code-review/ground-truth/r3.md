# Ground truth — review-r3

The PR extracts an `effectiveUnitPrice` helper, adds promotional pricing and a bulk discount to `src/pricing.js`, adds `formatOrder`, and updates the tests.

## Seeded defects

1. **dropped-empty-guard** — high — `src/pricing.js:25` (`orderTotal`)
   The pre-PR `orderTotal` threw `AppError('EMPTY_ORDER')` for an empty order (§4); the PR's rewrite drops the guard, so `orderTotal([])` now silently returns `0`. The PR also deletes the covering test (`tests/pricing.test.js`), which is why the regression escapes CI.

2. **promo-bulk-stack** — high — `src/pricing.js:13-14` (`effectiveUnitPrice`)
   A line with a `promoPrice` and quantity >= 10 gets the bulk discount applied *on top of* the promotional price (`unit = Math.min(promoPrice, price)` then `unit * (1 - BULK_RATE)`). §3 states the promotional price *replaces* the list price and is never itself discounted — only lines without a `promoPrice` are bulk-eligible. Note the PR's own tests never exercise the promo + bulk-quantity interaction, which is how this escaped.

## Decoys (not defects)

- `src/pricing.js:34-36` — `formatOrder` rounds once (via `orderTotal`) before formatting and ships a test; compliant with §2 and §5. Returning a string is its purpose.
- `src/pricing.js:11` — `Math.min(line.promoPrice, line.price)` is exactly what §3 prescribes for the promo-vs-list choice; the defect is the subsequent bulk discount, not the `min`.
- Constants extraction (`BULK_QTY`, `BULK_RATE`) and the `effectiveUnitPrice` helper split are behavior-neutral refactors.
- Every exported function has at least one test, so §5 is satisfied (the spec does not require branch coverage — but see defect 2 for why that matters).
