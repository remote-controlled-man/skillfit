# Ground truth — review-r2

The PR adds `applyLineTax` and `normalizeQuantities` (both `src/invoice.js`), `formatCents` (`src/money.js`), and happy-path tests for the two new functions.

## Seeded defects

1. **unregistered-error-code** — high — `src/invoice.js:20`
   A negative quantity is rejected with `AppError` code `QTY_NEGATIVE`, which appears nowhere in the §1 stable-code table; the table already defines `INVALID_QUANTITY` for exactly this case. Codes are public API, so inventing one requires a spec amendment.

2. **intermediate-rounding** — high — `src/invoice.js:22`
   `roundCents(line.unitPrice * (1 + taxRate))` rounds the per-line unit price, an intermediate factor that `subtotal` later multiplies by quantity and rounds again. §3 requires intermediates at full precision, rounded exactly once when the final amount is computed.

3. **input-mutation** — medium — `src/invoice.js:33`
   `line.qty = 1` mutates the caller's line objects in place; §2 requires exported functions to return new objects instead of mutating arguments.

## Decoys (not defects)

- `src/money.js:5-7` — `formatCents` rounds exactly once, ships a test, and returns a formatted string; compliant with §3 and §5.
- Tests: both new `invoice.js` functions ship tests in `tests/invoice.test.js`, so §5 is satisfied (it only requires tests to exist, not branch coverage).
- `src/invoice.js:14-16` — the `taxRate` validation uses the registered `INVALID_RATE` code and satisfies §4.
