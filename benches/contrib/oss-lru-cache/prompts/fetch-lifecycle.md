Background fetches expose several lifecycle problems in this lru-cache version. Consumers see internal Promise objects in `onInsert` callbacks. Evicting an entry during a refresh does not correctly dispose its previous value. A fetchMethod that returns a value synchronously can leave callers waiting indefinitely. Successful refresh completion can also send an unnecessary replacement abort back to the provider.

Repair these behaviors together. Invoke onInsert only for application values, with the correct add/update/replace reason. On eviction, dispose and disposeAfter should each receive the stale application value once with the evict reason. Accept synchronous fetch results, and do not abort a provider just because its own result is being stored. Preserve successful fetches, normal LRU behavior and explicit replacement cancellation. Add a new executable `*.test.mjs` regression that fails on the original implementation and passes after the fix. Existing tests, runtime adapter, metadata, helper modules and licenses must remain unchanged. Use only the local sources and Node built-ins; do not fetch a newer implementation.
