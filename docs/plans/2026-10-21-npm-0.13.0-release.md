## 计划review与边界

先完成版本准备和本地验证，再交付受保护main；必须在实际发布前完成预演包review。第6步是用户已授权的外部写入，不能把本地tar安装当成npm发布。第7步独立读取registry和固定Git来源，不从源码补漏；仅在临时新目录中写验证数据。

保留[上一轮18/18项实施计划](2026-10-20-install-transactions-and-archive-delivery.md)的历史结果。0.12.0及更早版本的recipe、收据和原件不改；新版本追加记录。发布工作流与[可信发布说明](../releases/trusted-publishing.md)已有版本占用检查、精确归档校验和隔离registry安装，不另建认证方式。发布后收据不能进入已经不可变的npm归档，在仓库追加并明确来源。

Node >=22适用于当前CLI/恢复工具；历史回放保留原来的Node 24.21.0、TypeScript/POSIX要求。常规测试保持离线。网络验证失败必须单列，不能把未执行项标为成功，也不自动重跑付费评估或更改真实配置。
