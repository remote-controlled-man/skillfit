# Complete the basic evaluation workflow

The user authorized completing the basic skillfit workflow, with independent work
in parallel and later optimization deferred. Real model/Agent evaluations remain
out of scope. Published evidence and private lab files are preserved.

## Required outcomes

1. Calibration cannot call an executor after an offline case hard failure. Its
   preview and live path check matrix/CLI readiness, preserve offline authentication
   as unknown, bind reviewed inputs, and retain stopped evidence.
2. Standalone bench checking and its verifier/oracle process trees cancel on
   SIGINT/SIGTERM. Nested checks reuse the active cancellation scope; cleanup does
   not detach running processes or leave temporary task copies.
3. Every judge invocation retains independent output, usage coverage, timing and
   failure receipts. Primary and judge costs are separate and totaled without
   rewriting paired quality statistics. Explicitly requested but unavailable
   judging is an error. Shared stop lines include all invoked roles.
4. Paired, trigger and calibration execution expose offline machine-readable
   plans, exact call counts, selectable tasks, configurable executor deadlines,
   spending stop lines and fresh output groups. JSON execution requires matching
   confirmation; no mode silently ignores requested controls.
5. All three evaluation types, including paired judging, support native saved
   reports and portable offline exports. Verification checks original receipts,
   sealed inputs and inventories. Replay makes no model calls; single-arm evidence
   never acquires an A/B efficacy claim or upgrade authorization.
6. Public help, driver Skill, JSON contracts, bilingual READMEs and mutable guides
   describe the implemented behavior. Historical formats remain readable with
   missing evidence explicitly unknown. No existing evidence is rewritten.
7. Deliver the reviewed implementation through commits, remote CI on three
   operating systems, merge/synchronization and the established manual release
   procedure. Verify the published archive and an isolated installation; never
   repeat an accepted upload because registry observation times out.

## Verification

Use deterministic fake executors/HTTP implementations and temporary home roots.
Regression checks must exercise each blocked path at zero executor calls,
between-call budget stops, failed and interrupted usage, stale plan rejection,
each native report kind, changed/missing originals, moved portable replay and
tampered inventories. Run `npm test`, bundled/contributed bench checks and the
existing first-run CI smoke. Preserve the existing statistical/adoption gates,
zero runtime dependencies, configuration-write safeguards and fresh-output
collision protections.

Completion requires observable evidence for every outcome above, including the
registry install. Tests and plan records alone do not establish a complete delivery.
