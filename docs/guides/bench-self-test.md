# Offline full-pipeline bench controls

Current-source addition, not yet published in npm 0.13.1. Build this checkout.
The availability requirement is a source build implementing bench-self-test
protocol 1, not a `0.13.1` version-string check. A minimum published release will
be assigned in the later release workflow; no unreleased npm version is implied.
`bench self-test` executes predeclared synthetic controls through the normal paired
runner, verifiers, receipts, statistics and native audit. It starts no Agent CLI,
API, judge or drafter and never authorizes adoption. Verifiers/oracles remain
trusted local programs: keep them offline; this is not a network sandbox.

## Preview and run

The bundled teaching bench has known benefit, harm, null and error suites:

```bash
node dist/cli.js bench self-test benches/_self-test/example --runs-root ./runs --run-group controls-001 --json --dry-run
node dist/cli.js bench self-test benches/_self-test/example --runs-root ./runs --run-group controls-001 --json --plan-sha <plan.sha256>
```

Use the actual hash from the preview, with the same fresh run-group and options.
JSON execution requires both; `--yes` cannot bypass the hash. Human execution
accepts a matching hash, confirmation or `--yes`. Declining returns a `planned`
result without writing. Preview executes no verifier/oracle/executor and creates
no output. It validates every suite/resource, even if only some are selected.

The positive installed/command suite has six discordant pairs and expects
`effective`, p=0.03125; the harmful output suite expects `ineffective` with the
same p. The null suite expects `inconclusive`, p=1. The error suite expects a
stopped prefix after exactly one injected error. These are known synthetic
answers, not measurements of a model or proof that your own real tasks have power.
Installed mode tests delivery and complete resource hashes, not native discovery.

```bash
node dist/cli.js bench self-test code-review --suite existing-mock-arms --runs-root ./runs --run-group review-controls-001 --dry-run
```

The code-review controls copy the original mock markers' output bytes into fixed
answer files. They retain the deliberately harmful summarize-s1 treatment. At one
trial per task the observed 3 improved / 1 regressed pairs yield p=0.625 and the
declared `inconclusive`; that expected result passes the self-test. Existing marker
files and ordinary `bench check` INFO probes remain unchanged. Adding controls
changes the current complete bench hash; historical runs need their original
sealed inputs rather than today's bench.

## Controls v1

`--controls <file>` is relative to the bench (default `controls.json`). Repeated
`--suite <id>` selects suites in file order; selected tasks run in bench order.
The [controls schema](../schemas/bench-controls.schema.json) describes the wire shape;
the runtime reader also checks relationships, resource safety and task compatibility.
See the [teaching controls](../../benches/_self-test/example/controls.json) for complete
examples rather than inferring expected behavior from a suite's name.

Each suite declares unique `id`, `purpose` (`benefit`, `harm`, `null`, `error`,
`custom`), `mode`, `agent`, unique `taskIds`, `trials` (1–20), per-task `arms` and
`expected`. Purpose is a label, not an assertion generated by the CLI. `inject`
requires `agent: null`; `installed` names a matrix agent solely for its project
Skill layout. The harness uses its small dedicated synthetic target and a fixed
workdir→task/arm/trial map, never the prompt to identify an arm.

| Action | Required task / resource | Behavior |
| --- | --- | --- |
| `{"kind":"output-file","path":"controls/answer.txt"}` | Output task; ordinary UTF-8 file inside the bench | Returns the fixed answer to the normal output verifier |
| `{"kind":"fixture"}` | Command task | Leaves initial files unchanged and returns a nonempty synthetic explanation |
| `{"kind":"oracle"}` | Command task with a registered oracle | Applies that local command to the disposable trial workspace; any error/nonzero exit is an execution error |
| `{"kind":"error","code":"SIMULATED_EXECUTOR_FAILURE"}` | Either task kind | Injects one controlled executor failure and stops this native suite |

Unknown fields/versions/actions, duplicate/unknown IDs, missing resources,
symlinks/nonregular files, absolute/traversal/Git paths and incompatible task/action
combinations fail before output creation. The complete bench, controls and answer
bytes are hashed/sealed. Source drift invalidates the plan or stops later calls.
Normal NOP/oracle integrity gates still run before execution. A parent output
directory that already exists, even empty, refuses the entire self-test.

`expected` declares `status: completed|stopped`, `statisticalVerdict`, and every
selected task's baseline/treatment `graded`, `passes`, `errors`. Completed suites
require every trial graded without execution errors. Optional `mcnemarPRange`
uses inclusive `minInclusive`, exclusive `maxExclusive`; omit it when unneeded
(including p=1). A stopped suite must declare `statisticalVerdict: null` and no p
range. Optional `errorCode` checks the exact supported injected failure. Only an
actual controlled error can pass a stopped error control; unexpected execution
errors, timeouts and signals cannot substitute for it.

Stopped counts describe only retained receipts, including an already graded arm
before its partner errors. There is no completed-pair inference, fake verdict,
replacement sample or fabricated receipt for an unstarted arm. Unreached declared
tasks remain listed with zero receipts. The first mismatch/unexpected error stops
the remaining suites; their entries stay `not-run`.

## Results, costs and replay

The [result schema](../schemas/bench-self-test.schema.json) uses `schemaVersion: 1`,
`kind: skillfit.bench-self-test` and statuses `planned`, `passed`, `failed`,
`not-configured`, `interrupted`, `error`. It includes the immutable reviewed plan,
expected/observed suites, refusal reasons, `synthetic: true`,
`simulatedExecutorInvocations`, `harnessModelCalls: 0`, and explicit ineligibility.
The full result is written to `<runs-root>/<run-group>/_self-test.json`, with its
plan in `_self-test-plan.json`; each suite is a normal native run below that parent.
These wrapper files do not replace the native receipts and audit.
If a top-level error prevents retaining that result, its generic error envelope
uses null invocation/duration counters rather than guessing zero; retained native
receipts remain the source of truth.

No model tokens or provider duration are invented: `simulatedUsage` explicitly
contains nulls. `localDurationMs` measures local checking/execution; native cost
tables retain unknown tokens and measured local elapsed time. A known-total zero
with unknown coverage is not free provider usage. All native executors remain
`kind: mock` / injected and cannot become eligible even when statistically effective.

Exit 0 means `planned` or all selected suites matched; missing controls return
`not-configured` / exit 1, mismatches return exit 1, and invalid parameters or
unexpected top-level errors return nonzero (normally 2). SIGINT/SIGTERM preserve
130/143, kill managed descendants and retain stopped receipts; they never count
as a passed error control. JSON stdout contains exactly one result, progress is
stderr. No automatic retry, live fallback or output overwrite is performed.

Read/export a **suite** directory, not the wrapper parent:

```bash
node dist/cli.js report eval ./runs/controls-001/known-benefit --json --replay
node dist/cli.js report eval ./runs/controls-001/known-benefit --export ./exports/known-benefit --json
node dist/cli.js report eval ./runs/controls-001/known-benefit --export ./exports/known-benefit --yes --json
node ./exports/known-benefit/reproduce.mjs
```

The normal [portable package](../reference/evaluation-reports.md) preserves controls in its sealed bench and the mock
identity. Moving it and removing the original run/bench does not change saved
statistics, unknown usage or ineligibility. Stopped suites replay retained costs
and observations without inventing a completed verdict or invoking an executor.
Verifiers execute trusted saved deliveries; replay does not rerun controls/models.

This first version supports paired inject/installed only. CLI options for trigger,
rules/MCP targets, judges or drafting are rejected explicitly; trials/tasks/mode
come exclusively from the control file. Single-arm activation self-tests remain
unsupported. Schema 1 and explicit
[schema 2 benches](../reference/bench-claims.md) can use configured paired controls; their
frozen `measurementScope.requestedClaim` is null (`not-applicable`). Schema 2 tasks
still require valid claims, but diagnostic-only execution gates on no efficacy
target and grants no adoption claim. Claims
never replace the controls file or its expected outcomes. Progress and future
work belong to [the remediation plan](https://github.com/remote-controlled-man/skillfit/blob/main/docs/work/current.md#status).
