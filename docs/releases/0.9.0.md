# skillfit 0.9.0

This release includes the Agent evaluation component. Use Node.js 22 or newer:

```bash
npx skillfit@0.9.0 --version
npx skillfit@0.9.0 --help
```

For a source checkout, `npm ci` and `npm run build` remain valid. The npm package
contains the component, driver Skill, schemas, examples, benches and offline
evidence archives; no runtime dependency or global installation is required.

## Verified publication

Published on October 15, 2026 in Asia/Shanghai (October 14 at
17:29:32.747 UTC). The [registry installation receipt](0.9.0-verification.json)
pins version/latest 0.9.0, archive integrity, source commit and 2,330 installed
files checked against the reviewed package. Version/help, request preview,
four evidence regrades and 130 numeric usage matches passed offline;
the reviewed source passed 513 tests. These checks added zero model calls.

## What the package delivers

- Agent-callable `eval --request`: strict versioned input, read-only preview,
  pinned plan, bounded calls and a separate adoption decision.
- Complete installed old/new Skill comparison; balanced pair order, symmetric
  deadlines and all-invocation costs, including failed, partial and unknown usage.
- Explicit efficiency policy and offline `report eval --json --replay` receipt
  checks. `reject` or `inconclusive` never authorizes adoption; no automatic
  installation, publication or upgrade occurs.
- The identical native untracked-file diff helper in both arms of new paired
  installed evaluations, with hash/integrity checks and native output/errors.
- Documentation, pinned real repository benches and append-only reproducible
  evidence, including the more expensive reading draft and prior interrupted work.

This is a release of measurement and evaluation tools. It does not claim that
a new debugging Skill has stable improvement. V5-reading is rejected;
v5.1 is an unvalidated draft. Actual helper adoption and net savings are untested.

## Publication checklist

1. Keep `package.json` and the lockfile root at the same version, with zero
   runtime dependencies and the existing development dependency graph unchanged.
2. Pass `npm test`, inspect `npm pack --dry-run --json`, and smoke the actual
   archive in an isolated directory: version/help, read-only request preview,
   native-tool descriptor and a frozen synthetic report. Replay the new evidence
   archive and verify exact quality/cost/acceptance equality without a model.
3. Merge the prepared source only after the three-platform CI checks pass.
   Retain the package SHA-256, size and verification receipt with the release work.
4. At actual publication, rebuild and rerun the package checks from the merged
   source. Verify 0.9.0 is still unused and use the repository's authorized npm
   account and required authentication. Publish that exact reviewed archive;
   never hide an authentication or publication failure as success.
5. Wait for the version to become installable, then confirm registry `latest`,
   version and package integrity and smoke an isolated install. Retain a public
   verification receipt and update the two READMEs' availability/version code
   blocks together with the verified release date.

npm scans new packages before they become installable, normally introducing
several minutes of delay. A successful publish response alone does not establish
availability; retain failed early reads and verify the registry installation.
See [npm's publish-time scanning announcement](https://github.blog/changelog/2026-07-28-npm-publish-time-malware-scanning-and-dual-use-metadata/).

The reviewed archive and publication receipt are retained in the dated
maintenance directory. Registry verification must match the exact archive
integrity and an isolated install must report 0.9.0; source smoke alone does
not establish successful publication. Release authentication is refreshed with
npm's normal browser flow, without changing non-authentication settings or
upgrading development tools.

For subsequent versions, see the [manual trusted publishing procedure](trusted-publishing.md).

The [ordered work plan](../plans/2026-10-14-evidence-and-release-sequence.md)
keeps new live experimentation behind a fresh spending decision. No model calls
are needed for package preparation or offline replay.
