# skillfit 0.9.1

This patch delivers the manual GitHub Actions release procedure introduced after
0.9.0. The CLI behavior, evaluation policy, runtime dependencies and published
experiment evidence are unchanged. It does not claim a Skill improvement.

## Release controls

- The workflow is manually triggered from `main` and defaults to package preview.
- The `npm-release` environment allows only the `main` branch. The npm trust
  binding identifies this repository, workflow filename and environment.
- A real publication requires an unused stable version and the exact inspected
  archive. OIDC authentication supplies the publication credential.
- Publication scanning is followed by exact version/latest/integrity checks,
  an isolated registry install, every packaged file and CLI version/help/request
  preview. Failed registry reads and reviewed archives are retained as artifacts.
- Offline tests and release verification invoke no model or agent CLI. No
  automatic Skill upgrade occurs.

See the [maintainer procedure](trusted-publishing.md). A preview or saved binding
alone does not verify OIDC publication: require a successful real publication
and its registry installation receipt before marking the release complete.

not a verified installation or a completed release. Recovery must verify the

## Verified registry recovery

npm published the version at 03:31:06.029 UTC on October 15, 2026 (11:31 in
Asia/Shanghai). The [independent installation receipt](0.9.1-verification.json)
matches version/latest and the exact first-upload archive. All 2,333 installed
files match that archive; CLI version/help/request preview pass, with zero
runtime dependencies and no global install. `npm audit signatures` verifies
the registry signature and attestation. The provenance pins the original
repository, main ref, workflow, source commit and publication run.
Fresh extraction of the registry-installed evidence archive also regrades four
deliveries and matches 130 numeric finals. The rejected candidate, 178-call
historical ledger and seven missing final usages retain their original meaning.

The original workflow's 41 failed reads and a later read-only attempt's 40
failed reads remain retained. Neither failed attempt was rewritten as success,
and there was only one upload. The registry installation was verified
independently after npm review; the original workflow remains failed.
The reviewed publication source passed 521 offline tests. Publication and
verification made zero model calls and establish no Skill improvement.

