# skillfit 0.9.1

This patch delivers the manual GitHub Actions release procedure introduced after
0.9.0. The CLI behavior, evaluation policy, runtime dependencies and published
experiment evidence are unchanged. It does not claim a Skill improvement.

## Release controls

- The workflow is manually triggered from `main` and defaults to package preview.
- The `npm-release` environment allows only the `main` branch. The npm trust
  binding identifies this repository, workflow filename and environment.
- A real publication requires an unused stable version and the exact inspected
  archive. OIDC authentication supplies the publication credential.
- Publication scanning is followed by exact version/latest/integrity checks,
  an isolated registry install, every packaged file and CLI version/help/request
  preview. Failed registry reads and reviewed archives are retained as artifacts.
- Offline tests and release verification invoke no model or agent CLI. No
  automatic Skill upgrade occurs.

See the [maintainer procedure](trusted-publishing.md). A preview or saved binding
alone does not verify OIDC publication: require a successful real publication
and its registry installation receipt before marking the release complete.

After registry verification, users can check the release with Node.js 22 or newer:

```bash
npx skillfit@0.9.1 --version
npx skillfit@0.9.1 --help
```

The historical [0.9.0 publication receipt](0.9.0-verification.json) remains
unchanged. The first OIDC publication uses a separate source commit, archive
integrity and verification receipt.
