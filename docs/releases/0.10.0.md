# skillfit 0.10.0

Published and verified as `skillfit@0.10.0` on October 16, 2026 in Asia/Shanghai
(October 15 at 17:46:05 UTC). The [verification receipt](0.10.0-verification.json)
pins the accepted archive, source, installation and offline feature checks.

## Delivered workflow

- Create a reply or code-editing starter, freeze a real failure or mine a fix.
- Inspect offline gate results with `bench check --json`.
- List/show cases and preview manifest edits/removals; apply with backup and
  validation. Removal keeps files and schema 1 remains nonempty.
- Select cases with repeatable `eval --task` or JSON request `taskIds`. Freeze IDs,
  order and full bench hash, preview only selected calls, retain all actual costs.
- Export paired native runs without a judge to a fresh portable directory with
  pinned inputs/implementation, original receipts, checksums and offline replay.
  Missing inputs reject export; stopped/partial evidence cannot become complete.
- Include optional whole-batch request spending guards introduced after 0.9.1.

See [case management](../case-management.md), [portable packages](../replay-packages.md),
[JSON bench checks](../bench-check-json.md) and the [component contract](../eval-component.md).
Exported project data requires review before sharing; exports stay local. External
verifier toolchains are the recipient's responsibility. Checksums detect changes,
not publisher identity. Legacy/redacted evidence retains its own dated recipes.

an extracted or isolated registry-installed package path and a fresh output parent:

```bash

```

It checks version/help, list/show, edit preview and first backup, removal with

receipts; zero model or agent CLI calls occur. The replay must reproduce exact
costs, remain synthetic/ineligible and retain `automaticUpgrade: false`. Generated
project/run files are cleaned; `feature-smoke.json` is retained in the output parent.
