## Spending guard results

Unreleased source now accepts an optional five-field `spendingBudget`, separate
from the relative adoption policy and the call-count ceiling. The proposal keeps
its original lines: total input 40,000,000; cached input 36,000,000; uncached input
5,000,000; output 1,250,000 tokens; accumulated agent duration 43,200 seconds.
These are proposed future lines, not permission to spend.

All twenty checks use injected offline executors and temporary homes. None
launches an agent CLI or a real model. The retained machine record names every
check. Relevant observed outcomes include:

- Each of the five independent lines prevents invocation two after invocation
  one reaches its line. No second workspace is allocated; receipt one remains.
- An input line of 5 with returned input of 10 retains 10 and stops the next
  call. Overshoot is not clamped or discarded.
- Absent counters, missing cache partition and cache greater than total input
  stop after one invocation. Unknown usage never becomes zero or complete usage.
- A malformed receipt stays byte-identical and is disclosed as invalid/unknown
  by stopped reporting. A failed executor's partial usage and a configuration
  guard error's complete returned usage remain accounted for, with no retry.
- Functional test failures consume budget. They remain observations, without
  being replaced or mislabeled executor failures.
- A complete four-call mock cohort produces eight before/after events that
  replay exactly from native receipts in the declared balanced order. A
  fabricated lower total fails semantic audit even after resealing its bytes.
- Changing a stop line invalidates the old preview before any call or run
  directory is created. The separate max-call ceiling still applies. Old
  requests omit the new optional field and retain their previous meaning.
- If only the final predeclared call reaches a line with complete evidence,
  the full cohort can finish; no extra call is made. An incomplete prefix
  cannot authorize adoption.

The guard checks between calls. **One in-flight call may exceed a line.** It is
not a provider hard token cap or a monetary bill. All actual agent invocations
count, including failures and excluded partners. Judge and trigger usage are
unsupported and explicitly rejected. Native plans seal stop lines and event
bytes; completed audit recomputes all states. Statistical formulas, exclusions,
adoption thresholds and the efficiency policy hash are unchanged. See the
[component contract](../docs/eval-component.md#input-and-execution).

Development exposed an actual reporting edge case: inconsistent cache counters
previously made stopped reporting throw. It now preserves the raw receipt,
reports the invocation as unknown and stops subsequent calls. Complete receipt
validation was not relaxed. Earlier failed setup/build attempts and test logs
remain in the private preparation directory; no task was replaced, no grader
assertion was weakened, and no failure was promoted to efficacy evidence.

## Reproduction and limits

On Node v24.21.0, `npm test` passes **556 tests, zero failures or skips**. The
twenty guard checks and thirteen bench checks are included in that total. Tests
needing HTTP use a local simulated server. No runtime dependency or package
version was added. Previously published evidence was checked against all 1,579
old file fingerprints and remains unchanged. The 130 historical cost records
were independently re-extracted from the three immutable archives and matched;
forecast values and numeric stop lines are unchanged.

From this source revision, build and run offline:

```bash
npm test
node dist/cli.js bench check benches/contrib/oss-skill-independent
node scripts/check-independent-readiness.mjs
node docs/examples/reproduce-independent-comparison-budget.mjs --verify-archives
```

The readiness script uses only owned temporary copies and injected executors,
prints `realModelCalls: 0`, and checks eight original/fix contrasts plus 20/13
passing checks. Optional `--out <new-json-file>` refuses replacement of an
existing record. Timestamps and measured synthetic durations vary; source and
bench hashes, named behavior outcomes and gate assertions are reproducible.
This local run does not attest other operating systems or Node versions.

No new quality delta, token savings, elapsed improvement or provider bill is
claimed. The planned 80-call comparison remains unexecuted. If separately
authorized, it still needs current power/environment checks and a fresh frozen
execution preview. Preparing this evidence does not authorize those calls.
